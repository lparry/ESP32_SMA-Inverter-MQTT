# P1 fixes — 1 October 2026

Clock reads and writes now use the configured inverter's Bluetooth address,
SUSy ID and serial number instead of broadcast destinations. Clock updates
reject missing and broadcast identities before sending any request. Existing
reply correlation and verification after writing remain in place.

HTTP input now passes through `BoundedWebServer`, which replaces the pinned
Arduino WebServer's request parser while retaining its routing, authentication
and response functions. The web UI uses GET and URL-encoded POST requests;
multipart, other body formats, Transfer-Encoding and Expect are rejected.
Limits apply before decoding arguments or invoking a route:

- 4,096 bytes for the request line and headers combined, and 32 header fields.
- 512 bytes for the request target, including query parameters.
- 4,096 bytes for the body, with a strictly parsed, nonduplicated Content-Length.
- 24 arguments across the query and body combined.
- Five seconds from accepting a connection to receiving a complete request,
  including clients that keep sending a trickle of bytes.
- At most 256 available bytes read per service call, without waiting for more.

The request buffer is a fixed member of the static server object. A malformed or
oversized request closes its connection without entering the upstream request
or multipart parser. Argument storage is released after each response.

Static compatibility was checked against the pinned Arduino core 2.0.9
[WebServer interface](https://github.com/espressif/arduino-esp32/blob/2.0.9/libraries/WebServer/src/WebServer.h)
and [request parser](https://github.com/espressif/arduino-esp32/blob/2.0.9/libraries/WebServer/src/Parsing.cpp).
Changes to that dependency should include a review of this subclass's protected
member usage.

Regression cases were added for clock destinations and invalid identities, HTTP
size and argument limits, malformed headers and encoding, incomplete multipart,
slow requests across timer rollover, form decoding, and request cleanup.

Executable validation completed on 1 October 2026:

- `python3 tests/host/run.py` passed the complete regression suite with
  AddressSanitizer and UndefinedBehaviorSanitizer enabled, including the new P1
  cases. The host configuration also exercises debug level 3 and syslog.
- The current workspace firmware compiled and linked successfully for
  `espwroom32` using PlatformIO 6.1.18 and the pinned ESP32 platform 6.3.2.
- All three CI configuration variants (no private configuration, the unchanged
  example configuration, and a partial configuration defining only `SCAN_RATE`)
  compiled and linked successfully using CI's pinned PlatformIO 6.1.19. These
  builds used an isolated temporary project, preserving private configuration.
- All firmware builds used Arduino core 2.0.9 and the pinned project libraries.
  RAM usage was 77,876 of 327,680 bytes; flash usage was at most 1,662,061 of
  1,966,080 bytes. Whitespace checks also passed.

No ESP32 was flashed. Live Bluetooth pairing, inverter clock updates, and device
network behavior remain outside the host tests and firmware compilation checks.
